# Cemu ARM64 NPU EXP v4 — Release — Flow Cache

실행 파일: `runtime/Cemu-npu-exp-v4.exe`. 시작 및 게임 중 제목은 **Cemu ARM64 [NPU EXP v4 - Release - Flow Cache]**다. 사용자가 개선을 확인한 NPU v3 Release를 바탕으로 GPU 움직임 계산 셰이더를 교체한 별도 시험본이다. SE/진단 버전이 아니다.

8×8 작업 그룹마다 원본 32×32 픽셀과 탐색 대상 40×40 픽셀의 RGB 값을 공유 메모리에 보관해 반복적인 imageLoad를 줄인다. 31,488바이트의 공유 메모리를 사용한다. 15×9×2 dispatch, 탐색 범위와 후보 수, 신뢰도 문턱, history/폐기 조건은 유지한다. NPU DLL·모델·전력 설정·해상도·출력 처리·그 밖의 셰이더는 v3와 동일하다. Cemu 소스에서는 시험본을 구분하는 제목만 변경했다.

## 독립 GPU 비교 결과

사용자가 2026-09-29 16:57:22~16:57:23에 실행했다. 30회 측정에서 움직임 계산 GPU 시간은 평균 **3.9068 → 2.9646ms**(0.9422ms, 24.12% 감소), p95 **4.2782 → 2.9700ms**였다. 두 셰이더의 실행 순서를 교대했다. 이는 해당 단계의 단독 GPU 측정이며 게임 전체 FPS나 GPU 사용률 감소를 뜻하지 않는다.

정지·이동·장면 전환·경계·반복 무늬·신뢰도 문턱 등의 검증/warmup/측정 총 45쌍에서 신뢰도와 유효 벡터가 일치했고, CPU에서 평가한 1080p 전체 합성 픽셀의 입력 프레임·좌표·valid/alpha 차이는 0이었다. 양쪽 모두 폐기하는 벡터 152개와 미사용 비용 기록 2,074개는 달랐다. 비용 차이는 최대 1/1,000,000이었다. 실제 GPU 합성 이미지 바이트와 게임 화질은 별도 검증 대상이다. 원본 자료는 `../NPU-Experiment/evidence/flow-cache-v4-20260929-165722-515.json`이다.

## 사용자 게임 시험

실행 후 기존과 같은 Vulkan 게임/장면에서 그래픽 설정의 **NPU frame generation (experimental, 1080p processing)**을 켠다. 시작 시 OFF이며 GPU LSFG와 동시에 켤 수 없다. v3와 동일한 옵션·출력 크기로 움직임 계산 시간, 원본/생성 FPS와 stale 횟수를 비교하면 실제 효과를 확인할 수 있다. 로그는 `runtime/portable/log.txt`에 저장된다.

창모드/전체화면 전환과 한 프레임 버퍼링은 v3 동작을 유지한다. ON이면 원본/생성 프레임 모두 내부 1080p 처리를 거치며, 생성 결과가 늦으면 기존 조건대로 폐기한다. GPU 움직임 단계가 빨라져도 약 19ms NPU 추론과 제출 시점 때문에 높은 원본 FPS에서 모든 생성 프레임을 사용할 수 있다는 보장은 없다. 표시 FPS는 present 수이며 실제 scanout 간격은 별도다.

v3 portable 설정/컨트롤러/게임 프로필/그래픽 팩을 별도 폴더에 복사했다. 저장 데이터는 기존 명시적 MLC 경로를 공유하며 원본 파일을 덮어쓰지 않았다. v3와 GPU LSFG 기준본은 그대로 있다. `NPU-RELEASE-BUILD.json`은 준비 시점 기록이고 `verify-build.ps1`은 파일·드라이버 검사만 수행한다. 이 v4 게임 패키지는 에이전트가 실행하지 않았다. 게임 성능·화질·전환 안정성은 사용자 시험으로 확인한다.
