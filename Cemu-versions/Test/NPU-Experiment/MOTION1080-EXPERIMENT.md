# 1080p 움직임 정렬 + 비동기 NPU 독립 실험

2026-09-29. 준비 상태이며 GPU/NPU 실측 전이다. 이 문서는 준비 파일의 해시와 함께 고정한다. 후속 실행 결과는 별도 결과 문서 및 evidence에 기록한다.

기존 ANVIL1080 revision 2의 GPU→공유 NPU→GPU 검증에 움직임 정렬과 지속 실행 작업자 스레드를 추가한다. Cemu 소스·실행 파일은 수정하지 않는다. 기준 Release GPU LSFG 실행 파일의 SHA256은 `ced1fa7b1291dd29fec78188165651634e6e8a9a07025afc2904e35b63737504`다. Cemu 연결 및 실제 게임 검증은 별도 후속 단계다.

## 처리와 검증 범위

1. GPU가 1080p 두 장을 생성한다. 4×4 픽셀 단위의 해시 색상을 사용한다.
2. 4×4 평균으로 480×270 이미지를 만든다. 16×16 원본 픽셀 블록마다 양방향 ±16픽셀 범위의 블록 매칭을 수행한다. 이동 정밀도는 4픽셀이다.
3. 양방향 이동 일치와 비용 임계값을 확인하고 중간 시점으로 워핑한다. 신뢰할 수 없는 영역은 현재 프레임을 보존한다. 정렬된 RGB 두 장을 U8 NHWC 6채널 공유 입력에 쓴다.
4. 지속 작업자 스레드가 공유 텐서에 직접 ORT Run을 호출한다. 주 스레드는 그동안 원본 이미지에만 독립적인 다음 입력 생성 작업을 제출한다. 추론 입력·출력·워핑 이미지는 재사용하지 않는다.
5. 작업자 완료 후 GPU가 ANVIL 잔차를 합성한다. 진단용 읽기와 CPU 검산은 측정 구간 밖에서 수행한다.

이 블록 매칭은 구조와 비용을 검증하기 위한 초기 구현이다. 작은 탐색 범위, 거친 이동 정밀도, 최근접 워핑, 단순 신뢰도 판정 때문에 빠른 카메라 이동·가림·복잡한 게임 장면의 품질은 입증하지 않는다. 합성 입력으로 보정한 양자화 모델도 실제 게임 품질 검증이 필요하다.

## 정확성 게이트

순서대로 정지, `(8,4)` 이동, `(-12,8)` 이동, 독립 장면 전환의 네 가지 입력을 사용한다. 각 입력마다 공유 메모리 QNN 결과를 일반 메모리 QNN 결과와 비교한다. 총 QNN 호출 8회, verbose 로그의 memHandle 8개와 RAW 8개를 확인한다. CPU fallback은 금지한다.

독립 Python oracle은 내부 블록의 알려진 양방향 이동 또는 장면 전환 거부 비율 99.5% 이상, 전체 정렬 입력 바이트, 신뢰도 마스크, 일반 메모리 대비 NPU 출력의 정확한 일치, GPU 잔차 합성의 채널 오차 1 이하를 검사한다. 장면 전환 출력은 현재 프레임과 정확히 같아야 한다. 서로 다른 네 입력·출력 해시를 요구한다.

진단 파일은 입력 12,441,600바이트, NPU 출력 6,220,800바이트, 합성 RGBA 8,294,400바이트, 워핑 A RGBA 8,294,400바이트, 순방향과 역방향 이동 각각 130,560바이트를 순서대로 저장한다. 총 35,512,320바이트다.

## 성능 측정과 한계

정확성 게이트가 통과해야 첫 실행 1회 + 예열 3회 + 측정 30회로 진행한다. 4가지 입력을 순환하며 마지막 입력 1을 정확성 게이트의 참조와 다시 비교한다. 측정 중 매 프레임 진단 읽기는 하지 않는다.

GPU timestamp: 원본 생성, 축소, 양방향 이동 계산, 워핑/입력 패킹, 잔차 합성, 독립적인 다음 이미지 생성. CPU wall: 전처리, NPU Run, 합성, 전체 하네스, 제출·펜스 대기, 작업자 제출, 완료 확인 대기. 측정 도구의 완료 확인에는 1ms sleep이 있으며 Cemu에 넣을 렌더 루프가 아니다. GPU 시간은 wall 시간에 포함되므로 합산하지 않는다.

NPU Run의 host 구간과 독립 GPU 제출·펜스 구간의 교집합을 기록한다. 이것만으로 실제 장치 연산이 동시에 실행됐다고 단정하지 않는다. Cemu 렌더링, 화면 표시, 실제 부하 경합과 프레임 간격은 측정하지 않는다. 드라이버 내부의 물리적 zero-copy도 입증 범위 밖이다.

## 작업자와 수명 관리

작업자 제출·결과 확인은 try-lock을 사용하고 추론은 mutex 밖에서 실행한다. 대기·실행·미수거 결과를 합친 용량을 제한하고 중복 슬롯을 거부한다. reset은 epoch만 변경한다. 취소된 작업도 입력 GPU 펜스의 소유권을 정리한 뒤 추론을 생략할 수 있도록 callback은 실행한다. 실행 중 취소 불가능한 추론 결과는 완료 후 폐기한다. stop/join은 종료 때만 사용한다.

슬롯은 결과 수거 후에도 GPU 소비 펜스가 끝날 때까지 호출자가 보존해야 한다. 독립 장치 시험은 하나의 실제 텐서 슬롯을 사용하며, 세 슬롯의 Cemu 파이프라인을 구현한 것은 아니다. GPU 제출은 모두 주 스레드에서 수행한다. 작업자는 QNN만 호출한다.

표시 순서 gate는 epoch, 크기, 마감 시각, 원본 프레임 ID를 검사한다. `원본 N → 중간 N+0.5 → 원본 N+1`만 허용하고 원본 N+1 뒤에 도착한 N+0.5는 거부한다. 실제 Cemu 연결에는 이 순서를 지키는 원본 버퍼링과 표시 간격 조절이 추가로 필요하다.

CPU 검사는 추론이 막힌 상태에서도 제출/확인/reset이 응답하는지, 취소·예외·종료·슬롯 재사용·표시 순서가 올바른지 확인한다. 별도 oracle 검사는 입력/이동/출력/합성/마스크 손상을 거부하는지 확인한다. 이 결과는 장치 검증을 대체하지 않는다.

## 실행

`run-motion1080-probe.ps1`의 기본 호출은 파일 해시와 드라이버 식별만 검사한다. 부모 ANVIL1080/interop/tuning manifest 검사도 연쇄 실행한다. GPU/NPU는 로드하지 않는다.

장치 실행은 사용자가 새 사용 시간을 승인한 후에만 `-Run`으로 실행한다. 최초 실패 시 성능 측정 게이트를 닫고 원본 증거를 보존한다. Cemu 실행, 화면 조작, 강제 종료는 포함하지 않는다. 드라이버는 NPU 30.0.224.10000, GPU 31.0.170.0이며 시험 전후 동일해야 한다.
