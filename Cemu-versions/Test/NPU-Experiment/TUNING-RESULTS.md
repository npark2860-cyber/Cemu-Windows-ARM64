# 1080p 상세 추적·공유 메모리 비교 결과

**이후 확인된 제한:** 바뀌는 GPU 입력의 공유 버퍼 시험에서 ORT1.24.4 BindInput의 사전 입력 복사 경로를 발견했다. 아래 공유 메모리 조건은 고정 입력을 먼저 채운 후 연결했고 Run만 반복했으므로,19.598ms 결과가 입력 복사 제거를 증명하지는 않는다. 일반 메모리 profile-off19.923ms 결과와 구분한다. 이후 직접 Run으로 수정한 작은 모델에서 GPU↔NPU 전달 검증5회는 통과했지만,1080p 성능을 새 경로로 다시 측정한 것은 아니다. 자세한 근거와 수정 결과는 `ZERO-COPY-RESULTS.md`에 있다.

2026-09-29. 사용자는 준비된 약 1~2분 비교 요청에 “진행해”라고 승인했다. 실제 장치 사용은 **08:06:20~08:06:58**에 끝났고 컴퓨터 사용 가능 상태를 알렸다. 이후에는 저장 파일만 분석했다. Cemu 실행이나 화면 조작은 없었다.

**QNN 상세 프로파일링을 끈 조건에서 1080p NPU 단독 추론이 평균 약 20ms로 줄었다.** 같은 세션 순서의 처음/마지막 기준 평균은 36.5719/36.5602ms로 거의 같았다. 현재 드라이버는 모든 실행 전후 `30.0.224.10000`이었다. 이전 드라이버와 섞인 비교가 아니다.

## 해석

처음/마지막 기준 평균 36.5661ms 대비, QNN 상세 추적만 끄면 **45.52%**, 공유 메모리 balanced 조건은 **46.40%** 시간이 줄었다. 이번 개선 대부분은 상세 추적을 끄는 변경에서 나왔다. ORT profile은 모든 조건에서 켠 상태이므로 완전히 계측을 제거한 운영 성능은 아니다. ORT kernel 평균도 각각 36.50 → 19.86 → 19.94 → 19.55 → 19.59 → 36.48ms로 움직였고, host 타이머만 잘못 짧게 잰 결과와는 일치하지 않는다.

일반 출력 버퍼 재사용의 추가 이득은 이 비교에서 보이지 않았다. 공유 메모리는 단순 profile-off보다 평균 약 0.325ms 짧았지만, 순서가 고정된 짧은 시험 하나이므로 작은 차이를 확정적인 개선으로 일반화하지 않는다. 지속 성능 모드도 balanced보다 추가 이득이 없었다. 현재 후보는 QNN profile-off와 balanced이며, 공유 메모리는 다음 프레임 입출력 실험에서 실제 이득을 다시 확인한다.

기존 36~38ms는 상세 프로파일링을 포함한 값이었다. 이번 결과를 반영하면 그 값만으로 1080p NPU 추론이 33.3ms 예산을 넘는다고 판단해서는 안 된다. 다만 이전 세대 드라이버보다 빨라졌거나 느려졌다는 결론은 이번 시험으로 내리지 않는다.

## 실행·출력 검증

- 여섯 프로세스 모두 exit 0, `QnnHtp.dll` 선택, CPU fallback 금지였다.
- 각 실행마다 ORT에서 QNN 단일 그래프 kernel 34개를 확인했다. 실제 UINT8 입력 `[1,1080,1920,6]`, 출력 `[1,1080,1920,3]`도 일치했다.
- 모든 출력은 이전 U8NHWC 기준과 바이트 단위로 같다. SHA256: `0432f24c82156b07286f45a6c8957673ea3e4d4aee55338dc11bf241bfc03eed`.
- 공유 메모리 조건은 실제 입출력 allocator `QnnHtpShared`와 고정한 현재 드라이버 RPC DLL 경로를 확인했다. 재사용 출력은 주소를 유지했고, Run 뒤 output synchronization까지 측정했다.
- QNN profile-off 조건에는 장치 내부 상세 시간을 보고하지 않는다. ORT profile의 kernel 시간은 QNN 호출 전체 시간이며 순수 NPU 연산 시간과 다르다.

## 적용 범위와 다음 단계

이번 결과는 **1080p NPU 단독 추론에서 30Hz의 33.3ms 예산에 들어온 짧은 시험**이다. 공유 메모리 조건의 평균 기준으로 약 13.7ms가 남지만, GPU와 NPU 간 전송·동기화, 움직임 추정/정렬, 잔차 합성 및 Cemu 동시 부하가 이 여유 안에 들어오는지는 아직 확인하지 않았다.

입력은 합성 영상 한 장을 미리 채워 반복 사용했다. 프레임이 바뀔 때마다 입력을 쓰고 출력을 소비하는 비용은 추가로 측정해야 한다. 공유 메모리 사용은 Vulkan/NPU 사이 무복사 연결이나 게임 보간 화질을 증명하지 않는다. ANVIL 입력은 정렬된 프레임 쌍이며 출력은 잔차이므로 독립적인 움직임 처리 경로도 필요하다.

다음 실험은 현재 profile-off/balanced 설정을 유지하며 프레임이 바뀌는 입력·출력 경로와 전송 비용을 확인하는 것이다. 장시간 발열, Cemu와의 동시 실행, 실제 게임 입력 보정 및 화질 검증은 별도 단계다. 새 장치 사용은 사용자와 다시 시간을 맞춘다. 기존 GPU LSFG 기준본과 네 가지 유지 버전은 변경하지 않았다.
