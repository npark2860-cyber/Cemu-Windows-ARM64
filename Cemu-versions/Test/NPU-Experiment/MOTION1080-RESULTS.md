# 1080p 움직임 정렬·비동기 NPU 검증 결과

2026-09-29 09:48:56.971~09:49:24.316 KST, 사용자 승인 시간에 독립 GPU/NPU 시험을 실행했다. 정확성 검사와 30회 성능 측정이 모두 통과했고 프로세스는 정상 종료했다. 사용 시간은 종료됐으며 추가 장치 실행은 하지 않았다. Cemu 실행·화면 조작·강제 종료는 없었다.

## 결과

정지, `(8,4)` 이동, `(-12,8)` 이동, 장면 전환의 네 경우에서 내부 검사 블록의 알려진 이동/전환 거부가 100% 일치했다. 전체 정렬 입력이 독립 CPU 계산과 정확히 같았고, 공유 NPU 출력은 일반 메모리 QNN 참조와 바이트 단위로 일치했다. GPU 잔차 합성 최대 채널 오차는 네 경우 모두 0이다. 장면 전환은 전체 현재 프레임을 정확히 보존했다.

워핑 신뢰 영역은 정지 99.2593%, 이동 96.5556%와 96.6574%, 장면 전환 0%다. 경계 또는 신뢰할 수 없는 영역은 현재 프레임을 사용한다. 99.5% 정확성 게이트는 경계를 제외한 내부 블록에 적용한 기준이며, 전체 이미지의 게임 보간 품질 점수가 아니다.

정확성 검사 QNN kernel 8회와 측정 34회 모두 QNNExecutionProvider만 사용했다. 정확성 로그에서 memHandle 8개/RAW 참조 8개를 확인했다. 성능 측정 마지막 이동 입력도 앞선 참조 및 진단 파일 SHA256과 정확히 일치했다.

전체 wall 최소 29.5189ms, 30회 모두 33.333ms 미만이었다. 이전 움직임 정렬 없는 기준의 전체 평균 21.3951ms와는 시험 구조가 달라 단순 성능 회귀로 비교할 수 없다.

전처리+NPU Run+합성 wall의 평균 합은 25.3439ms다. 전체와의 차이 5.4320ms에는 작업자 시작/완료 스케줄링, 시험 도구의 결과 polling 및 독립 GPU 작업 중 겹치지 않은 구간 등이 포함된다. 현재 증거만으로 이 차이를 전부 1ms sleep 탓으로 단정하거나 제거 후 속도를 보장하지 않는다. 후속 연결에서는 enqueue→추론 시작, 추론 완료→결과 수거를 각각 계측하고 렌더 스레드에서 완료를 기다리지 않아야 한다.

NPU Run host 구간과 독립 GPU 제출/완료 host 구간은 30회 모두 겹쳤고 교집합 평균은 0.5477ms다. 독립 작업의 실제 GPU timestamp 평균은 0.1162ms다. 짧은 별도 GPU 작업을 NPU 호출 동안 제출할 수 있음을 확인한 것이며, 실제 장치 연산 동시 실행이나 Cemu 부하에서의 지속 병렬 효율을 입증하지 않는다.

## 적용 범위와 후속 연결

이 시험은 ±16픽셀 탐색, 4픽셀 이동 정밀도, 최근접 워핑의 단순 블록 매칭을 사용한다. 빠른 이동, 물체별 이동, 가림 및 복잡한 게임 장면은 검증하지 않았다. 1080p 합성 입력에서 30Hz 생성 시간 기준을 충족했지만 실제 Cemu의 원본 30FPS 유지·60Hz 표시를 보장하지 않는다. 물리적 zero-copy와 실제 게임 화질도 미검증이다.

지속 작업자와 CPU 표시 순서 gate는 구현됐지만 Cemu에는 아직 연결하지 않았다. 독립 시험은 하나의 실제 NPU 텐서 슬롯과 측정용 완료 대기를 사용했다. GPU 작업은 모두 주 스레드가 제출했고 NPU 작업자에는 Vulkan queue 사용권을 주지 않았다.

Release 연결 시에는 FSR 후 원본 캡처, 슬롯별 입력 준비 펜스, NPU 작업자, GPU 합성/표시 펜스까지 수명 관리가 필요하다. 렌더 스레드는 결과 미완료 시 기다리지 않는다. `원본 N → 중간 N+0.5 → 원본 N+1` 순서를 유지하도록 원본 버퍼링과 표시 간격 조절을 구현해야 하며, 원본 N+1 뒤에 늦은 중간 N+0.5를 표시하지 않는다. OFF/크기 변경은 epoch로 결과를 무효화하되 사용 중 자원은 완료될 때까지 보존한다. 다음 실기 시험은 이 Release 연결본이 준비된 뒤 새 시간 승인으로 진행한다.

현재 검증된 GPU LSFG 실행 파일은 바꾸지 않았다. `../LSFG-Release/runtime-experiment/Cemu-lsfg-resize.exe` SHA256 `ced1fa7b1291dd29fec78188165651634e6e8a9a07025afc2904e35b63737504`를 다시 확인했다.
