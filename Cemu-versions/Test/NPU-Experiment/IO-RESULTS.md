# 1080p U8 입출력·NHWC 측정과 재측정

**후속 측정:** 현재 드라이버에서 QNN 상세 프로파일링을 끈 별도 비교는 평균19.9ms, 공유 메모리 조건은19.6ms를 기록했다. 아래34~38ms는 상세 추적을 포함한 이전 조건의 결과다. 33.3ms 예산에 대한 현재 판단은 `TUNING-RESULTS.md`를 함께 참조한다.

## 측정 후 확인된 NPU 드라이버 변경

사용자는 NPU 드라이버를 `30.0.224.10000`으로 업데이트했고 **두 번째 NHWC 측정(38.3844ms)부터 적용됐다**고 밝혔다. 현재 레지스트리와 연결된 장치의 `pnputil` 조회에서도 이 버전이 실제 사용 중임을 확인했다(기본 `oem73.inf`, 확장 `oem92.inf`, 드라이버 날짜 2026-07-25). 따라서 첫 NHWC 34.3743ms는 업데이트 전, 두 번째 38.3844ms와 세 번째 36.0121ms는 업데이트 후로 구분한다. 당시 드라이버 버전을 직접 수집하지 않았으므로 과거 적용 시점은 사용자 진술에 근거한다.

모델·입력·probe·실행 옵션은 같지만 첫 측정과 후속 측정의 시스템 드라이버 환경은 달랐다. 부팅 부하나 드라이버 변경 어느 하나를 성능 차이의 원인으로 확정하지 않는다. 아래의 업데이트 전 FLOAT32 기준 대비 후속 실행 단축률은 관측값 비교이며, 동일 드라이버로 통제한 비교가 아니다. 현재 DriverStore에 이전 패키지 `30.0.220.3000`도 남아 있지만, 이것만으로 첫 측정 당시 실제 사용 버전을 확정하지 않는다.

현재 적용 버전, 사용자 확인 내용, 실행별 구분은 `evidence/driver-update-context-20260929.json`에 추가 기록했다. 원본 실행 기록은 보존했고, 이 확인 과정에서 새 NPU 측정이나 드라이버 변경은 수행하지 않았다.

2026-09-29. 승인받은 세 모델 비교는07:32:37~07:33:17에 끝났다. 사용자가 “한번만 더 해볼수 있어?”라고 추가 측정을 요청해 같은 U8NHWC 모델만07:38:18~07:38:25에 재측정했다. 부팅 부하 가능성을 논의한 뒤 사용자가 “지금 괜찮아”라고 승인해07:42:27~07:42:33에 같은10회를 한 번 더 측정했다. 각 실행 종료 후 컴퓨터 사용 가능 상태를 알렸으며 세 사용 시간은 모두 종료됐다. Cemu/GPU/화면 조작/강제 종료는 없었다. 이후 분석은 저장 파일만 읽었다.

| 1080p 후보 | ORT Run 평균 | p50 | p95 | 장치 실행 중 대기 제외 |
|---|---:|---:|---:|---:|
| 기존 INT8, FLOAT32/NCHW I/O | 105.8997ms | 105.9127ms | 106.8497ms | 65.8272ms |
| UINT8/NCHW I/O | 92.0660ms | 89.0510ms | 115.6274ms | 60.3139ms |
| UINT8/NHWC I/O, 첫 측정 | **34.3743ms** | 33.2843ms | 39.9219ms | **15.6697ms** |
| UINT8/NHWC I/O, 재측정 | **38.3844ms** | 37.8506ms | 40.3649ms | **18.1193ms** |
| UINT8/NHWC I/O, 사용자 준비 후 세 번째 | **36.0121ms** | 36.0582ms | 36.2528ms | **18.1479ms** |

같은 `npu-io-probe.exe`, 모델/입력, balanced, detailed profiling, 첫 실행1회+warmup3회+측정10회다. NHWC의 재측정 평균은 첫 측정보다11.67% 길지만 기존 FLOAT32 I/O 후보 대비63.75% 시간 단축(약2.76배 처리량)이 유지됐다. 첫 NHWC 측정은67.54% 단축(약3.08배 처리량)이다. 변동 원인은 특정하지 못했으며 실제 주파수/발열/다른 부하는 계측하지 않았다. 각10회 표본의 p95는 nearest-rank 방식상 최댓값과 같다.

세 번째 NHWC 측정은 직전보다평균6.18% 단축됐고 최소35.6988ms/최대36.2528ms로 폭0.5540ms였다. 장치 실행 중 대기 제외는18.1193→18.1479ms로 거의 같았다. 사용자가 부팅과 겹쳤을 가능성을 언급했으나 부팅/다른 부하/클럭을 계측하지 않았으므로 부팅이 원인이라고 확정하지 않는다. 이 세 번째 측정은10회 모두33.3ms보다 길었다.

**NPU 추론 호출의 큰 개선은 재현됐다. 초당30장 생성의33.3ms 이내 동작은 아직 안정적으로 달성하지 못했다.** GPU 전처리·전송·합성 및 Cemu 동시 부하도 미측정이다. 장치 실행 구간은 ORT Run에 포함되므로 더하지 않는다. 이 값을 전체 파이프라인 시간으로 사용하지 않는다.

## 실행과 변환 검증

다섯 실행 모두 exit0, QnnHtp 선택/CPU fallback 금지, QNNExecutionProvider 단일 fused graph14회, 실제1080p 입출력 shape/type/layout, 결과 크기 및 유한값 검증을 통과했다.

NHWC 준비 초기의 layout pass에서는 Pad/Transpose 미지원 메시지가 있었지만, layout 변환을 적용한 최종 graph에서는257개 노드 모두 지원됐고 실제 실행은 QNN 하나로만 이루어졌다. 초기 경고만으로 최종 CPU fallback이 있었다고 판단하지 않는다.

기존 FLOAT32 I/O와 U8NCHW의 상세 profile에는 비합성곱 Transpose NODE 항목2개가 있었으며 입력 쪽 항목은평균약56.3Mcycles였다. NHWC 첫 측정과 재측정의 상세 NODE profile에는 해당 Transpose 항목이 **0개**였다. 새 ONNX 파일의 경계 Transpose를 QNN layout 변환이 상쇄한 결과와 일치한다. 개별 cycle 기록을 합산하거나 wall-time 절감률로 직접 바꾸지는 않는다.

## 출력 확인

동일한 논리 영상에 대해 저장된 결과를 배치에 맞게 복원해 CPU에서 비교했다.

- U8NCHW와 첫 U8NHWC 출력6,220,800개 byte는 **전부 동일**했다.
- U8NHWC 재측정 출력도 첫 측정과 **전부 동일**했다. SHA256 `0432f24c82156b07286f45a6c8957673ea3e4d4aee55338dc11bf241bfc03eed`.
- 세 번째 U8NHWC 실행도 위 출력 SHA256과 동일했고, 상세 profile의 비합성곱 Transpose NODE 항목은0개였다.
- U8 출력을 기록된 scale/zero point로 float 복원했을 때 기존 FLOAT32 I/O INT8 출력과는 최대 절대 오차0.00337356, RMSE0.00153611이 있었다. 작은 CPU 검사에서의 오차0과 구분한다. NPU 그래프 경계 변경에 따른 차이의 상세 원인은 아직 분리하지 않았다.
- 보정과 측정 입력은 합성 자료다. 위 비교는 게임 화면 화질, 잔상, 움직임 정렬의 정확성이나 시간적 안정성을 증명하지 않는다.

## 범위와 다음 단계

U8/NHWC 입력을 만드는 양자화·packing과 출력을 복원하는 dequantization은 ORT Run 밖이다. 이번 개선 수치를 최종 Cemu 프레임 시간 단축률로 간주하지 않는다. 남은 후보는 host/runtime 비용 개선, GPU 전처리와 U8/NHWC packing 통합, 합성 shader에서 잔차 scale 적용이다. 대표 게임 자료 보정과 같은 프레임 쌍의 품질 검사도 필요하다. 추가 장치 시험은 별도 사용 시간 승인 후 진행한다.

원본 기록과 상세 profile 순위, 출력 비교, 각 실행 파일·모델 해시: `evidence/io-results-20260929.json`.
사용자가 준비됐다고 알린 후의 세 번째 실행: `evidence/io-post-boot-results-20260929.json`.

- FloatNCHW: `htp-io-floatnchw-20260929-073237-944`
- U8NCHW: `htp-io-u8nchw-20260929-073256-962`
- U8NHWC 첫 측정: `htp-io-u8nhwc-20260929-073313-189`
- U8NHWC 재측정: `htp-io-u8nhwc-20260929-073818-415`
- U8NHWC 세 번째: `htp-io-u8nhwc-20260929-074227-880`

각 접두사 디렉터리 안에 raw output/ORT·QNN profile이 있고, 같은 이름의 `-run.json`과 `-console.log`를 함께 보존했다. 기존 Cemu GPU 기준본과 이전 실험 모델/도구/manifest는 변경하지 않았다.
