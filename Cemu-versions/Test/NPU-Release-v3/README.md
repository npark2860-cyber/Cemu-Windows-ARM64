# Cemu ARM64 NPU EXP v3 — Release

실행 파일: `runtime/Cemu-npu-exp-v3.exe`. 제목: **Cemu ARM64 [NPU EXP v3 - Release]**. 기존 GPU LSFG 기준본과 NPU v1/v2 패키지를 보존한 별도 Release 기반 실험이다. SE나 진단 변형이 아니다.

## 바뀐 동작

- 창 크기 제한을 해제했다. Vulkan SDR 출력에서 내부 처리는 1920×1080으로 유지하고 현재 창 크기에 맞춰 캡처·표시한다. 창모드↔전체화면 전환 시 history를 초기화한 뒤 자동으로 다시 처리한다. 크기 변경 직후에는 한 프레임 버퍼링을 다시 준비한다. 지원하지 않는 출력 형식이나 유효하지 않은 크기에서는 원본을 표시한다.
- 생성/원본 프레임의 오버레이를 한 번만 업로드한다. 두 번째 draw는 같은 버퍼를 읽고, 재업로드를 위한 생성 프레임 GPU 완료 대기를 제거했다. 버퍼마다 마지막으로 읽는 명령 ID를 추적해 실제 슬롯 재사용 때만 필요한 완료를 확인한다. 화면 재생성 시 기존 GPU drain과 이전 오버레이 재생 생략은 유지한다.
- 생성 프레임 present는 이전 원본 프레임 대기 기준을 갱신하지 않는다. 원본 present에서 기존 원본 프레임 기준으로 대기한다. 이미지 획득, 표시 세마포어, 필요한 버퍼 수명 대기는 유지한다.
- `[NPU-HOST]`에 캡처 제출, 모듈 호출, 생성 프레임 후 이미지 획득, 이전 원본 완료 대기, 이미지 획득 펜스, present queue 제한, `vkQueuePresentKHR` 시간을 평균/최대/횟수로 기록한다. 대기 제거의 실제 효과는 이 로그와 원본/생성 FPS를 함께 비교한다.

NPU DLL, ANVIL 모델, GPU 움직임 셰이더는 v2와 동일하다. 게임 렌더 해상도나 NPU 전력 모드는 바꾸지 않았다. GPU 움직임 계산의 약 5~6ms 비용은 이번 변경으로 직접 줄이지 않았다.

## 사용과 확인

Vulkan으로 게임을 실행하고 일반 설정 → 그래픽 → **NPU frame generation (experimental, 1080p processing)**을 켠다. GPU LSFG와 동시에 켤 수 없고, 앱 시작 시 OFF다. 실행 로그는 `runtime/portable/log.txt`다.

먼저 같은 장면에서 원본/표시 FPS와 `[NPU-HOST]`를 비교한다. F11로 창모드에 돌아왔을 때 새로운 출력 크기의 `Capture`와 증가하는 `runs`가 보이면 재개된 것이다. 전환 직후 짧은 준비와 계속 원본만 표시되는 상태를 구분한다. 속도 개선 및 전환 안정성은 실제 실행으로 확인해야 한다.

ON 동안 원본과 생성 프레임 모두 1080p를 거치므로 큰 출력에서는 네이티브 원본보다 선명도가 줄 수 있다. OFF는 원래 출력이다. 화면의 기존 레터박스까지 캡처한 전체 이미지를 처리 후 원래 창 비율로 되돌린다. 원본 한 프레임만큼 입력 지연이 늘며, 늦은 생성 결과는 폐기한다. 표시 FPS는 성공한 present 횟수이고 균등한 실제 scanout 간격은 미검증이다.

설정은 v2의 `portable`에서 필요한 파일만 한 번 복사했다. MLC는 기존 LSFG Release 시험과 공유하므로 기존 저장 데이터를 사용할 수 있다. 기존 설정/바이너리와 저장 데이터 파일을 덮어쓰지 않았다.

## 검증 상태

Release ARM64 빌드, 파일·드라이버 확인, 경로 및 프레임 순서 CPU 검사가 통과했다. 실제 ImGui 업로드/재생 함수를 추출해 Vulkan 호출을 CPU 대역으로 바꾼 검사에서 재생 중 쓰기 없음, ring 순환 시 마지막 읽기까지 대기, 잘못된 재생 거절을 확인했다. 이 검사는 실제 드라이버 동기화·게임 화질을 검증하지 않는다.

에이전트는 이번 v3에서 Cemu/GPU/NPU를 실행하지 않았다. 사용자 직접 시험으로 성능과 창 전환을 확인한다. `NPU-RELEASE-BUILD.json`은 빌드 시점 상태이며 `verify-build.ps1`은 파일 확인만 한다. 기존 `run-module-smoke.ps1 -Run`은 별도 사용 시간 합의가 필요하며 Cemu 표시 경로를 시험하지 않으므로 v3의 게임 검증을 대체하지 않는다.
