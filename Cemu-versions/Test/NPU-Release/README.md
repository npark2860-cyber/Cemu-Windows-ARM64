# Cemu ARM64 NPU EXP v1 — Release 기반 실험

이 폴더는 기존 `LSFG-Release/runtime-experiment/Cemu-lsfg-resize.exe`와 구분되는 NPU 연결 실험이다. SE나 진단 버전이 아니다. 기준 Git은 `c5205ccbc8ffe41129fbe921b5420a79ff283216`이며, 기존 Release의 FSR/GPU LSFG 변경 위에 별도 `CEMU_ENABLE_NPU` 옵션을 추가했다. 이전 GPU LSFG 실행 파일은 보존했다.

준비가 완료된 실행 파일 이름은 `runtime/Cemu-npu-exp-v1.exe`다. 제목에는 **Cemu ARM64 [NPU EXP v1 - Release]**가 표시된다. 정확한 파일 해시와 빌드/검증 상태는 `NPU-RELEASE-BUILD.json`을 기준으로 확인한다. 이 파일이 아직 없으면 패키지 준비 중이다.

## 사용

1. 이 폴더의 실행 파일로 게임을 실행한다. 그래픽 API는 Vulkan을 사용한다. 첫 게임 시작 때 NPU 세션과 1080p 자원을 준비하므로 시작 시간이 늘어날 수 있다.
2. 일반 설정 → 그래픽의 **NPU frame generation (experimental, Vulkan, 1080p output)**을 켠다. GPU LSFG 체크박스와 둘 중 하나만 켤 수 있다. 앱을 다시 시작하면 OFF다.
3. **출력 창의 실제 픽셀 크기가 1920×1080이고 SDR일 때** 동작한다. 게임 내부 렌더 해상도만 1080p로 바꾸는 것은 이 조건과 다르다. 다른 크기에서는 원본을 표시하고 화면에 이유를 알린다.
4. 끄면 원본 표시로 돌아간다. F11/창 크기 변경/긴 프레임 중단은 이전 결과를 무효화하고 다시 준비한다. 실행 중인 추론의 메모리는 완료될 때까지 보존한다.

독립 설정 파일은 `runtime/portable/settings.xml`이다. 기존 시험 설정에서 한 번 복사했으며 **MLC는 기존 LSFG Release 시험의 MLC 경로를 공유**한다. 게임/저장 데이터는 복사하거나 수정하지 않았다. 이후 게임을 실행하면 일반 Cemu와 같이 그 MLC에 저장 데이터가 기록될 수 있다.

## 구현된 처리

FSR 등 출력 처리 후, Cemu 오버레이를 그리기 전에 원본을 캡처한다. 고정 자원을 시작 때 준비하고 OFF에는 새 캡처/추론을 제출하지 않는다. NPU ON은 원본을 한 프레임 보관한다. 다음 렌더 때 준비된 중간 프레임을 보관한 원본보다 먼저 표시한다. 준비가 늦으면 중간 프레임을 버리고 보관한 원본을 표시한다. 첫 두 캡처는 첫 원본을 한 번 반복하여 지연을 만든다.

입력 지연이 원본 한 프레임만큼 늘어난다. 두 번의 present는 기존 Cemu 렌더 스레드에서 수행하므로 균등한 60Hz 표시 간격을 보장하지 않는다. 렌더 스레드에서 NPU 완료를 기다리는 코드나 polling sleep은 없다. 기존 Cemu present/오버레이용 GPU 대기는 남아 있다.

공유 텐서 슬롯 3개는 각자 입력 준비 명령/펜스, 워핑 이미지, 출력 합성 명령/펜스를 가진다. GPU 제출은 렌더 스레드만 수행한다. NPU 작업자는 입력 GPU 펜스를 기다린 뒤 추론만 호출한다. epoch/프레임 ID/마감 시각으로 지난 결과를 버리며, 새로운 원본 뒤에 오래된 중간 프레임을 표시하지 않는다. Cemu가 이미지 읽기를 같은 큐에 제출한 뒤 다음 슬롯 재사용과 입력 펜스가 실행되므로 사용 중인 버퍼를 NPU가 덮어쓰지 않는다.

표시 FPS는 성공한 present 호출을 집계한다. `Native`는 Cemu 원본 FPS다. 실제 디스플레이 scanout의 검증된 FPS는 아니다. `[NPU-PERF]`와 `[NPU-PROFILE]` 로그에 생성/폐기/슬롯 부족 및 NPU Run, 작업자 입력 펜스/시작 지연, GPU 축소/움직임/워핑/합성, 큐 제출 시간이 기록된다.

## 검증 범위

연결 전 독립 1080p 시험은 정지·두 방향 이동·장면 전환에서 정확성 검사를 통과했고, 전체 시험 평균 30.7758ms였다. 자세한 증거는 `../NPU-Experiment/MOTION1080-RESULTS.md`에 있다. 이 값은 Cemu 연결 후 성능이 아니다.

모션은 ±16픽셀 탐색, 4픽셀 정밀도의 초기 블록 매칭이다. 복잡한 장면·빠른 이동·가림의 화질과 합성 입력으로 양자화한 ANVIL 모델의 게임 품질은 미검증이다. NPU는 ANVIL 잔차 모델을 사용하며 GPU LSFG 모델의 NPU 이식 완료를 뜻하지 않는다. 현재 실험은 다른 네 유지 버전에 승격하지 않았다.

## 최초 실기 확인

컴퓨터 사용 시간을 합의한 뒤 진행한다. 먼저 OFF로 게임이 정상 표시되는지 확인하고, 1920×1080 출력에서 NPU를 켜 안정성과 Native/표시 FPS를 확인한다. OFF 복귀, F11 전환 후 지원 크기 밖에서의 원본 표시, 1080p 복귀와 다시 켜기도 확인한다. 오류가 나면 로그를 보존하고 강제 종료 반복이나 자동 재실행을 하지 않는다.

`verify-build.ps1`은 고정 파일과 드라이버를 검사할 뿐 Cemu/GPU/NPU를 실행하지 않는다. 게임에서의 실제 성공 여부는 별도 실행 결과에 기록한다.
